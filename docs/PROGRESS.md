### Bugs found and fixed

- The landing page's axe check failed on every run here (not just occasionally, as noted in Phase 3): axe sampled the hero text mid fade-in. WCAG checks now wait for running animations to finish.
- The setup screen read `premiumProvider` once, so a purchase made from setup wouldn't unlock categories until the screen was reopened. It now watches it.

### Not verified / limitations

- **Nothing is configured.** No Supabase project, Play Console app, Play subscription, Cloud service account, Pub/Sub topic or Paddle/Dodo account exists. Every external call was tested against fakes (Play API, Paddle HTTP, Google OIDC keys, Supabase JWTs) and a local Postgres, never the real services. Follow `docs/payments-setup.md`, then run the "Premium and accounts" section of `docs/qa-checklist.md` with a license tester.
- **Dodo field names** follow Dodo's docs as ported from Weblume and are unverified against the live API (same caveat as Weblume).
- **Supabase email-code sign-in** (`signInWithOtp` + `verifyOtp`) hasn't run against a real project; the email templates must show `{{ .Token }}`.
- **Premium content ships in the app bundle and website** (BUILD_PROMPT §11 allows this for v1), so a determined person could extract it; the cached entitlement is also on the phone. Downloading premium packs after verification is the upgrade path.
- **The web player stays free-only.** Web subscribers get Premium in the app; unlocking premium categories in `/play` needs the player to check the entitlement (small follow-up).
- Maintenance runs on a timer inside the API process (no job queue); fine for one instance, idempotent with several.
- No device run yet, so the Play purchase sheet, acknowledgement and RTDN have not been exercised end to end.

## Deploy pipeline (between Phases 4 and 5)

- `.github/workflows/ci.yml`: after every check passes on `main`, approval-gated deploys for the backend (Supabase migrations + API on Fly.io), the website (Cloudflare Pages, as a static export) and Android (Google Play, internal track by default). A new `api-image` job builds the API container on every push.
- New: `apps/api/Dockerfile`, `.dockerignore`, `apps/api/fly.toml`, `apps/web/public/_headers`, `supabase/config.toml`, `docs/deployment.md`.
- **Verified here:** actionlint passes; the API image builds and runs healthy as a non-root user against a migrated Postgres; `supabase db push` applies the migration and is a no-op on a second run; the site exports as static files and all 84 Playwright tests pass against `wrangler pages dev` (headers, clean URLs, 404s).
- **Not verified:** the deploy jobs against real Supabase, Fly.io, Cloudflare or Google Play (no accounts yet), and the approval flow on GitHub. Each target stays off until its `DEPLOY_*` variable is `true`. No App Store deploy (iOS out of scope).
